# Lesson Studio: notes for Claude Code

A creator studio and an on-device player for short explainer lessons (tech, AI, cyber), built for old phones and weak connections. [PLAN.md](PLAN.md) is the product plan, written by the user. Its Appendix C has the prices and API facts checked on 27 Oct 2026. Read §1 and §6 before changing the format.

## Layout
- `packages/spec`: the Lesson Package types (`src/types.ts`, v0.2: canvas elements, keyframes, overlays, transitions, camera), JSON Schemas (`schema/`) and `validatePackage()` with the budgets (`BUDGETS`). Keep the types, the schemas and the validator in step: the schema test validates every example against all three schema files.
- `packages/ops`: lesson operations shared by the studio, the MCP server and the worker. `applyOps` returns the inverse (undo); `rebase`; presets (`animate`); `OPS_SCHEMA` (the MCP tool schema); Firestore document shapes (`docs.ts`); `LessonStore` and `MemoryStore`. Every edit, by a person or an AI, goes through `applyOps`.
- `packages/player`: the player. `createPlayer(host, pkg, opts)` mounts into a shadow root.
  - Each template is in `src/templates/`; `templates/index.ts` adds overlays, camera, background and transitions to any scene. `src/canvas.ts` draws free elements and evaluates keyframes. `src/player.ts` has the clock, captions, controls and checks, plus `boxes()` and `elementAt()` for editors. `src/styles.ts` has the CSS.
- `packages/narrate`: narration. Gemini TTS requests and batch parsing (`gemini.ts`), WAV handling (`pcm.ts`), word alignment (`align.ts`), the narration track (`assemble.ts`), prices (`cost.ts`). Pure TypeScript; `scripts/narrate.mjs` is the CLI around it.
- `services/ai/align.py`: forced alignment with faster-whisper, run by the CLI from `services/ai/.venv` (pinned `requirements.txt`; av stays at 16.x, see the file).
- `apps/server`: MCP SDK v2 (`@modelcontextprotocol/server` 2.3.1, the 2026-07-28 spec).
  - `mcp.ts` has the tools, resources and prompts; `guide.md` is the format guide AIs read.
  - `stdio.ts` serves local clients and `main.ts` serves HTTP on 127.0.0.1:4320; `http.ts` holds the Express app.
  - `oauth.ts` is a small OAuth 2.1 authorization server, because the SDK only verifies tokens. `kv.ts` stores its clients, codes and refresh tokens.
  - `render.ts` draws frames with the player in headless Chromium; `preview/` is the MCP Apps view.
  - Stores: `stores/file.ts` (`.data/`) and `stores/firestore.ts`.
- `apps/studio`: the studio, a Preact app with signals and the Firebase JS SDK, on port 4330.
  - **Entry split:** `src/main.tsx` is the homepage (`views/Home.tsx`, `views/TopLine.tsx`) and must never import Firebase, or anything that does, statically; `src/env.ts` holds what it needs (emulators, the MCP address, the session flag). `src/studio.tsx` (lazy) is the signed-in app with Firebase. The e2e test "the homepage … no Firebase loads before sign-in" guards this.
  - **The editor shell** (`views/Editor.tsx`): rail and left panel (`Storyboard`, `Gallery.AddPanel`, `Layers`), `Stage` (pasteboard zoom and pan, guides, eight handles, rotate, snapping from `src/snap.ts`), `Inspector` tabs, `Transport`, the dock with the lesson-wide `Timeline`, `Palette` (Ctrl+K) and `Export` (R, and the shortcuts sheet). Workspace state (player, playing, zoom, guides, loop, rate, tabs, dock height) is in `src/editor.ts`.
  - **Theme:** dark tokens on `:root` in `src/styles.css`; `test/theme.test.ts` checks every text colour against every surface (4.5:1). Add a token there, not a colour in a rule.
  - `src/sync.ts` (`LessonSync`) is the live, optimistic sync: edits apply at once, then go out one batch at a time through `commit()`. A refused batch is rebased and sent again, and undo and redo are edits.
  - `src/editor.ts` holds the editor's signals. The screens are in `src/views/`: `Stage` (the player plus handles, hover, click to select, double-click to type), `Timeline`, `Storyboard`, `Gallery` (Add a scene), `Inspector`, `content.tsx` (template and element forms), `Animations` (word picker, animations, cues), `Checks` (with "Pick the new word"), `Preview`, `Lessons` (new lesson: blank, AI draft, example, file), `Settings` and `Connect`.
  - `src/presets.ts`: the scene gallery and a new lesson's first scenes. Every preset must validate with no warnings in every stage shape (`test/presets.test.ts`).
  - `src/parts.ts`: where a template part on the stage (`data-part`, see the player's `part()`) lives in the scene, and `setText` (one language). `src/convert.ts`: Convert to canvas, measured from an off-screen player. `src/timeline.ts`: the drag maths. `src/examples.ts`: the example lessons and lesson files. `src/ai.ts`: the callables.
  - `src/i18n.ts` holds the English and Arabic UI text; every key needs both, and the type system checks it.
  - On the emulators (`VITE_EMULATORS=1`, or no web config) the sign-in screen offers a test account.
- `functions/`: Cloud Functions (Node 22, europe-west1), not an npm workspace: its own lockfile, and only `firebase-functions` and `firebase-admin` installed. `build.mjs` bundles `src/index.ts` with everything else (the packages, `apps/server`'s MCP code, the studio's presets), bakes in the browser scripts the MCP server builds at run time on a PC, copies `guide.md` and the example beside the bundle, and writes `.env.lessons-studio-6b509` from `.env.local`. `keys.ts` (sealed AI keys), `gemini.ts`, `draft.ts` (the draft pipeline, pure) and `index.ts` (handlers, and the `mcp` HTTPS function).
- `firebase/firestore.rules`: members read and write lessons only as whole batches (rev + 1, scenes carrying that rev, an op log entry). Timings, `aiKeys` and `oauth_*` are server only. `firebase/storage.rules`: lessons' narration and scene voices in `media/<sha256>.<ext>`, and `uploads/<uid>/` for recordings on their way to `voiceClip` (see Scene voices); nothing else is readable. `firebase/storage.cors.json`: the studio's origins may fetch from the bucket (applied with `gcloud storage buckets update … --cors-file`). `firebase.json` also has Hosting (`firebase/public`, with rewrites of `/mcp`, `/authorize`, `/token`, `/register` and `/.well-known/**` to the `mcp` function). Emulators: `npm run emulators` (project `demo-lessonstudio`; Auth 9399, Firestore 8280, Functions 5401, Storage 9289 with bucket `demo-lessonstudio.appspot.com`, UI 4120; needs Java 21).
- `apps/playground`: Vite on port 4310. It serves `examples/` at `/examples/<id>/` (with range requests, for audio) and lists them at `/examples/index.json`.
- `examples/<id>/`: hand-written packages. `npm run narrate` writes `audio/`, and measured `timing/` and `captions/`; `npm run timing` writes estimated ones for languages without narration.
- `content/darsi/`: the 12 Darsi tutorial videos. `source/` (the packs' storyboards), `<id>/ar-EG.json` and `<id>/design.json` (written by hand), `lessons/<id>/` (generated by `scripts/darsi/convert.ts`; never edit). Its README is the authoring guide; `cy-1-1-2` is the reference lesson.
- `scripts/video/`: `stage.ts` (the player on a headless page, with `@lib/` and package files served from disk through `page.route`), `mp4.ts` (`npm run mp4`) and `package.ts` (`npm run package-lessons`). Output in `out/` (gitignored).
- `apps/studio/public/lib/v1/`: the shared library (cast, extra icons, the Darsi mark), from `scripts/build-library.mjs`. `packages/spec/src/library.ts` names it (`castPath`, `MARK_PATH`, `isIcon`, `isLibPath`); the player resolves `@lib/` with its `library` option and fetches `icons.json` only for lessons that use an extra icon (`Player.ready`).
- `.cache/narrate/` (gitignored): voiced sentences keyed by a hash of text, voice and settings; alignments; pending batches. Never delete it casually: it holds paid-for audio.

## Rules
- **Every frame is a pure function of time.**
  - A template's `update(lt, cs)` must set every animated property from those two arguments alone: no timers, no state carried between frames.
  - `Writer` only skips writes that wouldn't change anything.
  - The "same frame for the same time" test guards this.
  - MP4 export (`scripts/video/mp4.ts`) draws every frame with `seek(t)`, and skips screenshots when the stage's DOM didn't change.
- **Old phones.**
  - Motion is transform and opacity only.
  - No blur, filters, backdrop effects or blurred shadows; shadows are hard offsets.
  - No `aspect-ratio`: use padding boxes.
  - Redraw only while playing; the Lite, Frames and Text tiers redraw less often (`MIN_FRAME_MS`).
  - `npm run size` keeps the player under 30 KB gzipped (14.6 KB on 27 Oct 2026).
- **Right to left.**
  - Direction comes from the manifest's language track.
  - Latin runs inside right-to-left text go through `rich()` / `units()` (`<bdi>`), so "حقن الأوامر (Prompt injection)" keeps its order.
  - Flow diagrams mirror their x positions.
  - Time and the seek bar stay left to right.
- **Arabic.** Never use "·" as a separator (it reads as Arabic zero); use "،". The validator rejects it. Write Modern Standard Arabic, friendly, except the Darsi videos, which are Egyptian Arabic (`ar-EG`, rules in `content/darsi/README.md`). Example languages are marked `"quality": "machine"` until a native speaker reviews them.
- **Cues** name the spoken word in every language (`{ "en": "hides", "ar": "تخفي" }`). Matching ignores case, punctuation and Arabic diacritics, and allows up to 3 extra letters (clitics such as و). If a word isn't found, the validator warns and the cue fires at the scene's start.
- **Package text** only ever enters the DOM as text nodes, never as HTML. Package paths must be relative (`relPathOk`).
- **Narration.**
  - One TTS request per sentence: that makes sentence times exact. Words are timed by forced alignment, not estimated.
  - Batch by default, at half price; `--now` only for quick checks.
  - The API key lives only in `.env.local` as `GEMINI_API_KEY`. The user sets it. Never print, log or read it; check only whether it's set. Requests send it in the `x-goog-api-key` header, never in a URL.
  - A narrated language's timings are measured, so `npm run timing` leaves them alone. After editing its script, re-run `npm run narrate -- <id>`. The validator's `timingStale` error catches timings that no longer match the words.
  - The manifest's `voice` records what made the audio. The cache key adds the per-language hints (`voiceFor`), so changing a voice or style re-voices that language.
- **Animation (v0.2).**
  - Keyframes can anchor to spoken words per language (`resolveWhen`), like cues.
  - Free elements mirror in right-to-left languages unless `fixed`; code and charts stay left to right.
  - The validator warns on budgets: 300 KB per language, 120 KB per image, 40 elements per scene, 12 tracks moving at once.
  - Transitions move only the incoming scene, with transform and opacity.
- **MCP server.**
  - Tools act as one actor (uid plus via), and every lesson read or write checks membership.
  - Online access needs `LS_PUBLIC_URL` and `MCP_TOKEN_SECRET`; then every HTTP request needs a token. Without `LS_PUBLIC_URL` it serves this PC only.
  - Never weaken the sign-in: PKCE S256 only, exact redirect URIs, single-use codes, rotating refresh tokens, allowlisted verified emails.
  - Never print secrets. `.secrets/` and `.data/` are gitignored.
  - The in-chat preview speaks the MCP Apps protocol itself (`preview/view.ts`), keeping it at 19 KB gzipped; don't swap in the ext-apps `App` class (167 KB).
  - In the render page, move the clock with `seek(t)`, not `renderAt(t)`: a resize redraws at the clock's time.
- **The studio is private.** Only accounts with the `studio` custom claim may use it: the Firestore rules (`signedIn()`), every callable (`signedIn` in functions/src/index.ts) and the studio itself (a "This studio is private" notice) require it, and the MCP sign-in only admits `LS_ALLOWED_EMAILS`. Give or take access with `node scripts/grant-access.mjs <email> [--revoke] [--emulator]` (revoking also ends open sessions). Only Google sign-in is enabled in the real project. Tests give their accounts the claim (`signIn` in e2e/studio.spec.ts, `signUp` in functions/test/emulator.test.ts, `db()` in apps/studio/test/sync.test.ts); keep a "without access" case in each.
- **Studio and sync.**
  - Every write goes through `commit()` in `packages/ops/src/docs.ts`: the server in a transaction, the studio in a batch the rules check. `sceneRevs` lets a reader tell when its snapshot is whole, and `commit` (an id) tells its own echo from someone else's write.
  - Every operation returns a precise inverse (`applyOps`), so undo never discards another person's or an AI's change. A new operation needs one too, plus a test in `ops.test.ts` "undo next to someone else's edits".
  - Tests that clear the emulator use project `demo-lessonstudio-test`, never `demo-lessonstudio`, which is the one people use in the browser.
  - The Firebase web config in `.env.local` is public by design; service-account keys never go there (`.secrets/`).
- **Scene voices** (the user asked to record or upload audio, and that moving scenes keep it).
  - Each scene has its own voice per language: a clip in the bucket by content (`media/<sha256>.opus`, Opus 48 kbit/s mono 24 kHz, `clipObject`) with its words and sentences timed from the clip's start, in `lessons/{id}/voice/{lang}` (`VoiceDoc`, packages/ops/src/voice.ts; server-written, members read). A clip says the script it was made for (`text`); `clipFits` compares it with the scene's narration.
  - `voiceTrack(scenes, lang, clips)` puts a language together in the lesson's order: each fitting clip, else silence as long as the text would take (estimated words). Moving, copying or removing scenes keeps every voice; a changed script silences only its scene. Its timings are "aligned", "tts" or (nothing voiced) "estimated".
  - The studio builds the track in the browser (apps/studio/src/voice.ts: each clip fetched and decoded once, placed to the sample, a WAV in memory) and plays it through `studioPackage`; the stage plays again at once after a move. This needs the bucket's CORS (`firebase/storage.cors.json`).
  - Recording and upload (views/Voice.tsx): the inspector's Voice cards (listen, kind, whether it was made for the current script, record, upload or drop a file, remove, undo), the recorder (script, microphone and level, count-in, live waveform, review), the timeline's Voice row (each scene's waveform; a silent scene is a button to record it) and the storyboard's dots. The take goes to `uploads/<uid>/` (the Firebase SDK's multipart upload, from `upload()`), then the `voiceClip` callable cleans it up (trim, loudnorm, lead-in and tail; scripts/lib/voice.ts), times it (`timeRecording` in packages/narrate: sentences at the longest pauses, words spread by letters), stores the clip and deletes the upload. "remove" and "undo" (the doc keeps what each change replaced in `prev`) use the same callable.
  - `exportVideo` builds the same track on the server (`voicePackage`, `putVoiceTrack`). Lessons without voice documents still use the older single narration file (below).
  - `scripts/darsi/push.ts` cuts each language's narration into scene clips at the scenes' starts, keeping the Whisper word times (`clipsFromNarration`; reassembled, the words land within a millisecond); it never replaces a clip someone made in the studio. `--voice-only` writes only the voices.
- **Narration as one file (older lessons).**
  - The audio lives in the bucket by content, `media/<sha256>.<ext>` (`mediaObject`), named in the manifest's `assets`. Anyone may fetch a media file by name (an `<audio>` element can't send a sign-in); the name appears only in documents only members read. Listing and writing are refused; only the server writes.
  - Audio plays only with timings measured from it: `toPackage` drops a language's audio on estimated timings, and `currentTimings` keeps a measured timing only while the scenes and their words still match the script.
  - The studio reads `lessons/{id}/timing/{lang}` live (`measured`, `peaks`); the Voice row then draws `TimingDoc.peaks`. `exportVideo` reads the file from the bucket (`LS_MEDIA_BUCKET`) and checks its hash.
- **AI keys and drafting.**
  - Never handle a person's real key: they paste it in Settings. Never log it, return it or store it unsealed; `aiKeyStatus` returns only the last four characters.
  - `GEMINI_API_BASE` (a stand-in for Gemini) is honoured only when `FUNCTIONS_EMULATOR` is true, so deployed functions always call Google.
  - The draft prompt teaches the format with `guide.md` and gallery presets; when you change the format, both stay in step.
  - Emulator tests: `LS_FUNCTIONS_EMULATOR=1` runs `functions/test/emulator.test.ts` (it runs the Gemini stand-in on port 4599).
- **Security content** teaches defence and awareness, never step-by-step attacks (PLAN.md §11).
- **Imports:** use `.ts` extensions, `import type` for types, and no parameter properties or enums. The scripts run the TypeScript sources directly with Node 24's type stripping.
